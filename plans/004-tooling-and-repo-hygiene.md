## Why this matters

The repo carries **two** pre-commit systems and **neither runs**. `git config core.hooksPath` points at `.husky/_` (husky shims), but `.husky/` contains no `pre-commit` script, so husky's shim exits 0 silently. Meanwhile `.vite-hooks/pre-commit` (containing `vp staged`, the vite-plus staged-checks runner configured in `vite.config.ts`'s `staged` block) sits in an identical shim structure that git never consults. Net effect: the configured staged lint/format checks have never run on any commit. Separately, build artifacts (`.vite/deps/_metadata.json`, `.vite/deps/package.json`) are git-tracked, and the `web-vitals` dependency and `src/logo.svg` are referenced nowhere. This plan converges on the vite-plus hook system (the stack the repo migrated to in commit `2952739`), removes husky/lint-staged, and untracks the dead weight.

## Steps

### Step 1: Switch the prepare script to the vite-plus hooks

In `package.json`, change:

```json
"prepare": "husky"
```

to:

```json
"prepare": "git config core.hooksPath .vite-hooks/_"
```

Then run it once: `bun run prepare`

**Verify**: `git config core.hooksPath` → `.vite-hooks/_`

### Step 2: Remove husky and lint-staged

1. Delete `husky` and `lint-staged` from `devDependencies` in `package.json`.
2. Run `bun install` to update `bun.lock`.
3. Delete the `.husky/` directory: `rm -rf .husky`

**Verify**: `bun install` exits 0; `git diff bun.lock | grep -c 'husky\|lint-staged'` shows only removals; `ls .husky` → "No such file or directory"; `bun run typecheck` and `bun run lint` still exit 0.

### Step 3: Prove the hook actually fires

Run this self-contained check (creates a deliberately unformatted staged file, expects the hook to either fix or reject it, then cleans up fully):

```sh
printf 'export const   x=1\n' > hook-canary.ts
git add hook-canary.ts
git commit -m "hook canary (will be undone)" ; echo "commit exit: $?"
# Whether the commit succeeded (hook auto-fixed) or failed (hook rejected),
# the hook must have RUN — its output (vp check) must appear above.
git reset --hard HEAD~1 2>/dev/null || git reset hook-canary.ts
rm -f hook-canary.ts
```

**Verify**: the commit attempt printed `vp check` output (proof the hook ran). If the commit went through silently with no hook output, the wiring failed — STOP and report `git config core.hooksPath` plus the contents of `.vite-hooks/_/pre-commit`. Confirm cleanup: `git status` is clean and `git log --oneline -1` shows the pre-canary commit.

### Step 4: Untrack `.vite` artifacts

```sh
git rm -r --cached .vite
```

Add a line `.vite` to `.gitignore` (alongside the existing `.tanstack`/`.output` entries).

**Verify**: `git ls-files .vite` → empty; `git status` shows `.vite/deps/*` deletions staged and `.gitignore` modified; the files still exist on disk (`ls .vite/deps`).

### Step 5: Remove dead dependency and dead file

1. Delete `"web-vitals": "^5.3.0"` from `devDependencies` (check both dep sections; it is expected in `devDependencies`) and run `bun install`.
2. Delete `src/logo.svg`: `git rm src/logo.svg`

**Verify**: `grep -rn "web-vitals\|logo.svg" src vite.config.ts package.json` → no matches; `bun run typecheck`, `bun run lint`, and `bun run build` all exit 0.

## Maintenance notes

- Fresh clones get hooks via `bun install` → `prepare` → `git config core.hooksPath .vite-hooks/_`. If vite-plus later ships its own hook-install command, the prepare script can delegate to it.

- `.vite/` stays on disk as a local cache; it's now ignored. If other `.vite`-adjacent artifacts appear tracked later, extend `.gitignore` the same way.
